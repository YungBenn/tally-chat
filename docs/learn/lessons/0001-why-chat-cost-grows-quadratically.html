Why a 10-turn chat costs 47 turns' worth

Tokens, statelessness, and the triangle hiding inside every chat bill.

The win. By the end you can compute the input tokens and cost of any turn in a thread by hand, and explain the design doc's headline: "what the user types is 1 to 2% of the bill" (design doc §2).

1. A token is the billing unit

Models don't read characters or words. Text is split into tokens: chunks that can be a word, part of a word, a character, or a byte. On older Claude models a token is about 3.5 English characters; Claude 4.7 and later use a newer tokenizer that produces about 30% more tokens for the same text. (Anthropic glossary: Tokens)

You pay per token, quoted per million tokens (MTok), and the two directions have different prices. For Claude Sonnet 5.5: (Anthropic pricing, checked Oct 2026)

DirectionWhat it isPrice
Input tokensEverything you send in the request$2 / MTok
Output tokensEverything the model writes back$10 / MTok

Output is 5x the price of input. That ratio will matter in section 5. You've already seen these counts: they're in the usage block of every response.

"usage": {
  "input_tokens": 30,
  "output_tokens": 309
}

2. The API remembers nothing

This is the one fact everything in the design doc rests on. In Anthropic's words: "The Messages API is stateless, which means that you always send the full conversational history to the API." (Messages API: multiple conversational turns)

So a chat isn't one long connection. It's a series of independent HTTP requests, and each one carries the whole thread so far. Watch the request body grow:

// turn 1
{ "system": "You are concise.",
  "messages": [
    { "role": "user", "content": "Plan a 3-day Tokyo trip" }
  ] }

// turn 2: everything from turn 1, resent
{ "system": "You are concise.",
  "messages": [
    { "role": "user", "content": "Plan a 3-day Tokyo trip" },
    { "role": "assistant", "content": "Day 1: ... (400 tokens)" },
    { "role": "user", "content": "Swap day 2 for Kyoto" }
  ] }

// turn 3: everything from turns 1 and 2, resent again
...

That full array is the context window: the model's working memory for this one request. (Anthropic glossary: Context window) Every token in it is billed as input, every time.

The 400-token answer from turn 1 is paid for once as output on turn 1, then again as input on turn 2, turn 3, turn 4... for the life of the thread. A bad answer you never fix keeps charging rent. That's design doc S2's whole argument.

3. The formula

Take a thread with a system prompt of S tokens, user messages of u tokens, and answers of a tokens. The input for turn k is:

input(k) = S  +  (k − 1)·(u + a)  +  u
           │         │               └ the new message
           │         └ every earlier user + assistant pair
           └ system prompt, every single time

Our baseline thread for this lesson: S = 500, u = 50, a = 400, 10 turns.

TurnInput tokensof which you typed (this turn)
155050
21,00050

...+450 each turn

Total25,750500

Ten turns, but 46.8x the input of a single turn. And of 25,750 input tokens, the user typed 500: 1.9%. That's the design doc's "30 to 50x" and "1 to 2%", derived from one line of arithmetic.

Why it's quadratic

Each turn's input grows linearly (+450 per turn). But the bill is the sum of all turns, and the sum of a linearly growing series is a triangle. Triangle area grows with N². Closed form:

total_input(N) = N·(S + u)  +  (u + a)·N·(N − 1) / 2
                 └ linear        └ quadratic: wins as N grows

5. Practice

Do these from memory of the formula. No scrolling up. Baseline: S = 500, u = 50, a = 400, Sonnet 5.5 prices.

a. How many input tokens does turn 20 send?

HintS + (k − 1)·(u + a) + u, with k = 20.

b. What does turn 20 alone cost in dollars (input + output)?

Hint9,100 × $2 / 1,000,000 + 400 × $10 / 1,000,000.

c. In a 20-turn thread, which change saves more money?

System prompt: 300 × 20 turns = 6,000 input tokens = $0.012. Answers: 2,000 fewer output tokens ($0.020) plus each shorter answer is re-read by every later turn: 100 × (0 + 1 + ... + 19) = 19,000 fewer input tokens ($0.038). Total $0.058, almost 5x more. This is design doc S11's "a shorter answer saves twice."

d. Why does turn 10 cost more than turn 1, on the same model?

Statelessness. The API has no memory, so your app resends the entire thread on every request.

6. Optional: see it in real numbers

If you have an Anthropic key, the token counting endpoint returns the input count for a request without generating a reply. Send the turn-1 body, then the turn-2 body, and compare input_tokens. Or paste text into the OpenAI tokenizer to see how text splits into tokens (a different tokenizer from Claude's, but the same idea).

Where this lands in tally.chat

This lesson is cost driver #1 in doc §3: conversation accumulation, quadratic, dominant over everything else. The doc attacks the triangle three ways:

  • Make it smaller: S2 fork (drop bad turns), S3 condense (replace old turns with a summary), S11 shorter answers.
  • Make it cheaper: S5 prompt caching. Same triangle, but most of it billed at a fraction of the input price.
  • Make it visible: S9 inspector shows the user the bars you just played with.

Next lesson is the big one: prompt caching, and why the doc calls it "where the 60x lives."
